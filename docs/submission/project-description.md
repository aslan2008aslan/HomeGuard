## 二、问题来源

家庭服务机器人正在从「遥控执行」走向「自然语言交互」，但真正的瓶颈不在单点能力，
而在**任务闭环**：用户说一句「去看看阳台的绿萝要不要浇水」，机器人需要自己决定
去哪里、看什么、怎么判断、判断不准怎么办、判断完之后怎么反馈。

这一连串动作，目前多数家庭机器人产品要么依赖预编程的固定流程，要么只能完成单步问答，
**无法形成「移动—观察—推理—验证—反馈」的完整闭环**。

更关键的是，家庭场景是**长尾的**。今天要检查绿植，明天要看看窗户关没关，
后天要确认老人有没有按时吃药。如果每个场景都要单独开发一套流程，
家庭机器人永远无法真正进入普通家庭。

因此，真正有价值的不是「会浇水的机器人」，而是一个**能用自然语言即时定义任务、
自主完成闭环、并在失败时自我纠错的通用任务引擎**。

**问题来源的真实性**：本项目的场景不是虚构的教学案例，而是源于真实家庭看护需求 ——
双职工家庭白天无人、独居老人缺乏巡护。项目从这一需求出发，
选择其中一个最小可用场景做完整验证。

## 三、项目目标

本次参赛，选择**「绿植是否缺水」作为第一个验证场景**。目标不是做一个功能繁多的
家庭助手，而是用一个真实、可运行、可复现的小场景，验证框架的核心能力：

1. **自然语言任务理解** —— 用户用一句话描述巡检需求，系统自动解析为可执行步骤。
2. **AGH 驱动的任务编排** —— 由模型完成「导航→观察→推理→验证→反馈」的步骤规划，
   AGH 负责工具调用、执行反馈与记录留存。
3. **视觉推理与不确定性处理** —— 模型基于摄像头图像判断绿植状态，
   输出带置信度和依据的结构化判断；置信度不足时自动调整拍摄策略重试。
4. **异常与边界处理** —— 展示至少一次失败自纠错（如角度不对、光线不足导致判断置信度低
   → 重新采集 → 二次判断成功）。
5. **任务切换能力** —— 同一套系统，不修改核心代码，输入一个新的自然语言任务
   （如「看看厨房窗户关没关」），验证框架的通用性。

### 本次边界

诚实界定作品边界：**只把「绿植缺水检测」这一个场景跑通、跑稳、跑出可核查的证据链**。
不堆场景，不拼功能数量，而是用一个场景证明框架的完整闭环能力。

### 4.2 关键设计决策：调用方向

这是本项目最容易被理解反、也最能体现协议层价值的一点。

**不是**上位机去连小车，**而是小车主动 dial 上位机的 AgnesHub**。

MHS 协议原文：

> "A device dials AgnesHub, registers its state, tools and data sources, then takes calls
> and streams data. The model never talks to a device directly: it acts through AgnesHub,
> which checks every call against what the device declared."

| | 说明 |
|---|---|
| ✅ AGH + AgnesHub 部署在上位机 | 模型在上位机侧做编排 |
| ❌ 「上位机调小车接口」 | 不是在上位机写适配层去调车 |
| ✅ 实际机制 | 小车主动 dial 上位机的 AgnesHub，注册自己声明的工具/数据源/状态 |
| ✅ 模型的调用路径 | 模型通过 7 个设备工具，经 AgnesHub **间接**调用小车 |

**这一设计带来三个直接好处**：

1. **设备侧不开任何入站端口**，只需一条出站 WebSocket，攻击面最小。
2. **协议层由 AGH 全包**，我们不必在上位机写任何「调小车接口」的胶水代码。
3. **每次调用都按设备自己的申报校验** —— 设备声明了什么能力就只能被调用什么，
   这本身就是可直接展示的协议级安全证据。

### 4.3 模型侧工具表（固定 7 个）

模型侧固定只有 7 个设备工具，**设备增减不改变工具表**：

`list_devices` · `read_device` · `call_device` · `set_device` ·
`stop_device` · `watch_device` · `unwatch_device`

设备自己的工具（`drive` / `turn` / `halt` / `say` / `listen` 等）是 `call_device` 的
**参数**。这一点对可扩展性很关键：新增设备或新增设备工具都不会改变模型的工具表。

> **`read_device` 声明了 `returnsImages`** —— 摄像头图片能直接进模型上下文。
> 这是「视觉推理」能落地的技术前提。

### 4.4 设备能力申报

`turpi-01` 向 AgnesHub 申报的能力：

| 工具/源 | 说明 | 状态 |
|---|---|---|
| `drive` | 前进/后退指定距离（米），带进度与暂停 | ✅ 已验证 |
| `turn` | 原地转指定角度（度） | ✅ 已验证 |
| `change_view` | 换视角（转向的语义封装） | ✅ |
| `aim_camera` | 云台 —— 总是报错（硬件无扭矩） | ⚠ **设计如此**，故意保留以诚实报告失败 |
| `halt` | 急停 | ✅ |
| `say` | 朗读文字（无 TTS 时回退提示音，如实报错） | ✅ |
| `listen` | 听几秒并报告响度（peak/rms） | ✅ |
| `front` | 摄像头图像源，640×480 JPEG | ✅ 已验证 |
| `pose` | 航位推算位姿（无编码器，标注 `ok: false`） | ✅ 诚实标注 |
| `mic` | 麦克风音频源（按需录音，不常开） | ✅ |

**设备自带安全底线**：限位、急停，以及与 hub 断连时自行停下。

### 4.6 视觉判断方法

模型基于摄像头 JPEG 图像判断绿植状态，输出**结构化判断**：

```json
{
  "conclusion": "需浇水 / 暂不需浇水 / 无法判断",
  "confidence": 0.0,
  "evidence": ["观察到的具体视觉依据"],
  "retry_recommended": false
}
```

**交叉验证手段**：湿度计读数与图像判断相互对照，避免单靠图像导致误判。

**不确定性处理**：当 `confidence` 低于阈值时，判定为「判断不可靠」，
触发重拍策略（`change_view` 换角度），再执行二次判断。

### 4.7 为什么用 MHS 而不是自建接口

MHS 是 AGH 自带的设备接入协议层，本体是 agnes-harness 仓库里的 `packages/mhs`。
选择它的理由：

- 设备库很薄（`Device` + `dev.tool(...)` + `dev.source(...)` + `await dev.run(url)`），
  树莓派 5 无压力。
- 设备端只需一条出站 WebSocket，不需要开放任何入站端口。
- 设备描述里如实申报能力，AgnesHub 按申报校验每次调用。
- 提供 `mhs-check` 一致性测试台，可对自研设备做标准化验收。

> **官方验收范围不包括真机。** 验证记录写明
> "Real browsers, paid models, external services, **physical devices**, and other platforms
> were outside this acceptance scope"，且 MHS 部分声明
> "there is no hardware compatibility list or certification"。
> 即真机接入这件事官方自己也没端到端跑过 —— 这既是风险，也是本作品的价值所在
> （**首个真实硬件接入案例**）。

## 五、Agnes Harness 执行流程

### 5.1 一条自然语言指令的完整链路

任务输入：**「去看看阳台的绿萝要不要浇水」**

| 步 | 动作 | 对应能力 | 可留证据 |
|---|---|---|---|
| 1 | 解析意图 → 规划步骤 | 自然语言任务理解 | 对话记录、计划文本 |
| 2 | `list_devices` / `read_device` 看电量与位置 | 状态感知 | Activity 标签页的调用卡 |
| 3 | `call_device(goto/plant)` 开到绿萝前 | 导航 | 设备调用卡 + `pose` 源轨迹 |
| 4 | `read_device(front)` 取图，模型判断含水状态 | 视觉推理 | **图片进上下文的记录 + 结构化判断** |
| 5 | 置信度不足 → 换角度重拍 → 二次判断 | 不确定性处理 + **失败自纠错** | 两次拍摄与两次判断的完整对照 |
| 6 | 输出结论 + 置信度 + 依据，建议浇水 | 反馈 | 最终答复 |

### 5.2 AGH 在流程中承担的核心作用

指南要求「AGH 不能只用于生成说明文字或外围辅助，必须在作品的核心任务流程中发挥实际作用」。
本项目中 AGH 承担的是**不可替代的执行底座**：

| 环节 | AGH 的作用 | 若去掉 AGH 会怎样 |
|---|---|---|
| 任务规划 | 模型编排步骤序列 | — |
| 能力调用 | 把模型意图转为对设备的实际调用，并**按设备申报校验** | 无法调用真实硬件 |
| 图像进上下文 | `read_device` 的 `returnsImages` 把相机变成模型可读输入 | 视觉推理无从谈起 |
| 执行反馈 | 每次调用返回实际结果（含失败原因），回灌给模型 | 模型无法知道执行成败 |
| 安全约束 | `stop_device` 总是允许的；设备声明被违反时拒绝调用 | 失去急停与边界约束 |
| 记录留存 | 完整调用记录可供导出与人工核查 | 无法满足提交要求「可供人工核查的执行记录」 |

**若不使用 AGH**，上述六个环节全部需要自行实现，且无法满足赛事的记录与核查要求。

### 5.3 实测已验证的调用序列

## 六、验证方法

对应指南第六节「基本完成要求」中「设置明确的结果验证方法」与
「展示至少一次异常、失败或边界情况的处理过程」。

### 6.1 链路可用性验证（先于一切）

**教训**：只看 `netstat` 里有 `ESTABLISHED` 就认为通了，是**错误的**。
实测多次出现**半死会话**：TCP 连接在，但 MHS 数据不流。
**「能出图」不等于「能动」；「ESTABLISHED」不等于「能调用」。**

按顺序全过才算真可用：

| # | 判据 | 命令 / 调用 | 实测结论 |
|---|---|---|---|
| 1 | 进程**恰好 1 个**，`PPID 0` | `docker exec turbopi ps -o pid,ppid,cmd \| grep turpi_device` | ✅ |
| 2 | 日志**在增长** | `docker exec turbopi wc -c < /tmp/turpi.log`，隔 8 秒再看 | ✅ |
| 3 | socket 稳定**不换端口** | `ss -tn \| grep :4180`，多采样几次 | ⚠ 曾反复更换，已修 |
| 4 | **send-Q 不持续堆积** | 同上，看第二列 | ⚠ 遗留未定位 |
| 5 | AGH 侧 `available` 且**源时间戳秒级** | `read_device(turpi-01, sources=["pose"])` | ✅ |
| 6 | 相机能出图 | `read_device(turpi-01, sources=["front"])` | ✅（有 41% 丢帧） |

### 6.2 执行结果验证（三层证据）

| 层 | 验证方式 | 本项目实现 |
|---|---|---|
| **调用层** | AGH 的调用记录：每次 `call_device` 的入参、返回值、时间戳 | 可从 AGH 导出（⚠ 待导出） |
| **物理层** | 设备实际动作与状态变化 | `drive 0.5` → 实测返回位移与耗时；轮子实测转动 |
| **判断层** | 模型基于图像的结构化判断 + 置信度 | 输出 conclusion / confidence / evidence |

### 6.3 交叉验证

单一证据链不足以证明结果正确，因此采用交叉验证：

| 主证据 | 交叉验证 | 作用 |
|---|---|---|
| 图像判断（模型） | 湿度计读数 | 避免图像误判；两者不一致时需人工复核 |
| 航位推算位置 | 调用返回的耗时与速度 | 位置自标 `not trusted`，**不单独作为精确值** |
| 电池状态字段 | 串口 SDK 直读（7306 mV） | 字段恒空，直读为权威 |

### 6.4 诚实标注原则

本项目对不可靠的数据**一律如实标注**，而非掩盖：

- `pose` 源因**无编码器**、位置靠时间积分会漂移，**主动标注 `ok: false`**；
  `drive` 返回值中也带 `position not trusted`。
- `aim_camera` 因**硬件无扭矩总是失败**，**故意保留该工具**以诚实报告失败，
  而不是从工具表里移除它来掩盖硬件限制。
- 电池字段恒空但值可直读，已在文档中区分「字段上报」与「直读值」。

### 6.6 已知限制（如实记录）

1. **云台不可用** —— 舵机接受位置写入（读回正确）但带不动负载；且厂商 ROS2 代码存在
   舵机 ID 冲突（`servo_controller.yaml` 的 id 1/2 与云台冲突）。
2. **无编码器** —— 位置靠时间积分，会漂移，故 `pose` 源诚实标注 `ok: false`。
3. **转向换算缺陷** —— 厂商用 `max_linear_speed` 换算角速度，导致占空比只有线速度的 1/7；
   需 `angular.z≈2.0` 才能驱动轮子。
4. **AgnesHub 无鉴权/加密** —— 只能在可信局域网内监听网络地址，
   **禁止暴露公网**（官方文档明确要求）。
5. **低压保护失效** —— 见 F2，演示前必须人工看电压。
