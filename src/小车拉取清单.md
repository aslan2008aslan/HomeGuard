## 七、关于 `mhs-check` 一致性验收（⚠ 已查明阻塞原因，**未运行**）

### 7.1 阻塞原因已查明

`mhs-check` 一直无法运行，真因是：

- 容器内缺少 `jsonschema` 模块
- → `agnes_mhs/device.py` L36 `from .schema import PROTOCOL`
- → `agnes_mhs/schema.py` L14 `from jsonschema import Draft202012Validator`
- → `ModuleNotFoundError: No module named 'jsonschema'`
- → 整个 `agnes_mhs` 库无法导入，`mhs-check` 无法启动

**已修复**：在容器内安装 `jsonschema`（实装版本 **4.26.0**）。
实测现在 `import agnes_mhs` 与 `agnes_mhs.check --help` **均正常**。

### 7.2 为何仍未运行（队伍决定）

`mhs-check` 采用「测试台 + 设备连接」模式，运行它必须先：

1. **停掉正在运行的设备程序**（PID 7453）—— 设备同一时刻只能连一个 hub；
2. **停掉 keeper 服务** —— 否则它会立即把设备程序重新拉起。

**后果**：会**中断当前正在使用的 AGH 会话**，且运动类测试会真实移动车辆。

**队伍决定（2026-10-13）：选择暂不运行**，理由：

- 已有 4 份 AGH 诊断导出包（含完整调用链）**已满足指南对「执行记录」的要求**；
- `mhs-check` 属**增强型证据**，非硬性缺项；
- 避免中断现场演示/录制窗口。待视频重录完成后可随时补跑。

### 7.3 补跑要点（备查，无需现在执行）

1. 停 keeper 与设备程序（`systemctl stop turpi-keeper`；容器内 `pkill -9 -f turpi_device`）
2. 启动测试台：容器内设 `PYTHONPATH=/opt/agh_mhs/python/src`，运行 `python3 -m agnes_mhs.check --no-motion --report /tmp/mhs_report.json`
3. 另一个终端让设备连测试台（`python3 /tmp/turpi_device_patched.py ws://127.0.0.1:8800`）
4. 恢复保活：`systemctl start turpi-keeper`

> ⚠ **端口注意**：`mhs-check` 默认端口是 **8800**，不是 4180。
> `--no-motion` 可跳过会移动车辆的测试；`--interactive` 用于人工判断的物理项。
> 无 `fail` 时退出码为 0；有 `fail` 时退出码非零。
