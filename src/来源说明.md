### 2.1 它做什么

设备程序运行在树莓派 Docker 容器 `turbopi` 内，主动 dial 上位机的 AgnesHub，
申报工具与数据源，然后接受调用、推送数据。文件头部自述（原文）：

```
Runs INSIDE the turbopi docker container, where the ROS2 workspace lives,
and dials AgnesHub running on the operator's PC.
```

### 2.2 申报的能力（与真机实测一致）

**工具（7 个）**：`drive`、`turn`、`change_view`、`aim_camera`、`halt`、`say`、`listen`

**数据源（3 个）**：`front`（图像）、`pose`（位姿）、`mic`（音频）

> ✅ **交叉核对**：以上与 AGH 侧 `list_devices` 实测返回的
> `tools: drive, turn, change_view, aim_camera, halt, say, listen;`
> `sources: front (image), pose (pose), mic (audio)` **完全一致**。

### 2.3 安全设计（文件头部自述，原文）

```
Safety model:
  - on_stop zeroes the chassis AND centres the gimbal, and returns fast
  - every motion tool zeroes the chassis in a finally block
  - motion loops call checkpoint(), so pause/stop take effect promptly
  - unsafe() refuses motion when the battery is low
```

> ⚠ **诚实说明**：最后一条 `unsafe() refuses motion when the battery is low` 在当前部署下
> **实际不生效** —— 因为设备读电池走 ROS 话题 `/ros_robot_controller/battery`，
> 而该话题实测 `Publisher count: 0`，导致 `mv` 恒为 `None`，判断条件永不触发。
> **详见** `../../04_运行与验证证据/测试样例_失败.md` F2。

### 2.4 已包含断线重连补丁

文件末尾含 `MHS-RECONNECT` 标记的重连逻辑（L863–L921）：

| 设计 | 作用 |
|---|---|
| 退避重试（2→4→8→16→30 秒封顶） | 避免疯狂重连打爆网络 |
| **重连前先 `stop_chassis()`** | 防止重连瞬间底盘失控 |
| 仅识别连接类异常 | 其他异常也打印原因 |

> 补丁申请见 `../../docs/设备掉线根因与重连方案.md`（团队原创）。

## 五、❌ 明确**未**包含的第三方组件

以下组件**不随本仓库分发**，仅作为运行依赖：

| 组件 | 归属 | 位置 | 获取方式 |
|---|---|---|---|
| TurboPi SDK / 例程 | Hiwonder（厂商） | `~/board_demo`、`~/turbopi`、`/home/pi/demo` | 同型号硬件预装 |
| ROS2 工作区与厂商节点 | 厂商预装 | `~/ros2_ws` | 同型号硬件预装 |
| `ros_robot_controller_node.py` | 厂商 | `~/ros2_ws/src/driver/ros_robot_controller/` | 同上 |
| `agnes_mhs` 库 | Agnes（Apache-2.0） | 容器内 `/opt/agh_mhs/python/src` | `packages/mhs/python` |
| ROS2 Humble / picamera2 / PyAV | 第三方开源 | 系统与容器预装 | 各自官方渠道 |

> **`turpi_device.py` 会 `import` 厂商 SDK 与 `agnes_mhs`，但本仓库只交付团队自己写的代码**，
> 不含任何厂商源码副本。这是刻意为之，以符合指南「第三方闭源组件不得公开」的要求。
