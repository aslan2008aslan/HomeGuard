## 一、样例定义

| 项 | 内容 |
|---|---|
| **样例编号** | B1–B4 |
| **类别** | 边界（Boundary） |
| **目的** | 证明系统在临界条件下行为可预期、不会失控 |

**边界与失败的区别（本文档采用的定义）**：

- **边界**：系统仍在工作，但处于临界状态或数据质量下降（如丢帧、定位不可信、接近阈值）
- **失败**：调用确实失败或系统确实出错，需触发处理逻辑

## 二、候选边界样例

### B1 · 定位不可信（无编码器导致的漂移）

| 项 | 内容 |
|---|---|
| 触发条件 | 设备无编码器，位置靠时间积分推算 |
| 观察现象 | `pose` 源返回 `ok: false`；`drive` 返回中含 `position not trusted` |
| **已实测** | ✅ 返回原文：`... position not trusted. Took 5 s.` |
| **模型侧实际应对（新增）** | ✅ **已在 AGH 导出中核实**：模型在任务要求「不依赖定位」下，**完全未使用坐标导航**，只靠 `front` 图像判断朝向与距离；同时如实转述 `position not trusted` |
| 系统行为 | **主动标注不可信**，而非谎报精确值 |
| 期望处理 | 模型不应将米数当精确值使用；任务判断应以视觉为主 |
| 实测证据 | 见 `AGH执行记录与设备调用.md` §2.2、§2.6；`agh-diagnostics-8f055bc6-*.zip` |
| 状态 | ✅ **已完成**（现象与模型侧应对均有记录） |

### B2 · 图像源丢帧 / 设备瞬时离线

| 项 | 内容 |
|---|---|
| 触发条件 | `front` 图像源在网络/负载压力下丢帧；或心跳超时导致设备短暂不可用 |
| 观察现象 | AGH 侧提示 `Attention: front: 41 % lost`；极端时 `turpi-01 is offline ... front: 0/1 per second` |
| **已实测** | ✅ 丢帧率实测 **41%**；✅ **新增**：任务中设备一度 `offline`（`events.jsonl` seq 647），**随后自行恢复** |
| 系统行为 | 取图偶有延迟；模型重试后继续，**任务未中断** |
| 期望处理 | 取图失败时重取一次，而非直接把空数据当结论 |
| **模型侧实际应对（新增）** | ✅ 模型在 `offline` 后重新 `read_device`，确认恢复后继续任务 |
| 状态 | ✅ **已完成**（丢帧率与一次真实的离线-恢复均有记录）|

### B3 · 判断置信度不足（感知边界）

| 项 | 内容 |
|---|---|
| 触发条件 | 拍摄角度不佳、光线不足或逆光 |
| 观察现象 | 模型输出的 `confidence` 低于阈值 |
| 期望处理 | 判定为「判断不可靠」→ `change_view` 换角度重拍 → 二次判断 |
| 状态 | ⚠ **待跑通并记录**。这是项目介绍中已承诺的能力，**也是视频镜头 5 的核心** |
| 需要留存 | **两次拍摄与两次判断的完整对照**（缺一不可） |

### B4 · 调用被拒绝（协议边界）

| 项 | 内容 |
|---|---|
| 触发条件 | 底盘资源被占用（`busy`），或电量低触发安全闸（`unsafe`） |
| 观察现象 | AgnesHub 按设备申报**拒绝**调用并说明原因 |
| 期望处理 | 模型读到拒绝原因后**降级处理**（就近观察、回充电座等） |
| 状态 | ⚠ **待实测**。这是 MHS 的独有亮点，**强烈建议展示** |
| ⚠ 重要提醒 | **`unsafe` 路径当前失效** —— 因电池字段恒空，低压保护永不触发（见失败样例 F2）。若要演示该边界，需先应用 `tools/fix_battery_topic.ps1`，或改用 `busy` 路径 |
