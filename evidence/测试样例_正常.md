### 2.2 为什么算「正常」样例

即使文件名带「失败」，本次执行的实质是**一次完整的正常闭环**：

1. 任务输入 → 解析（自然语言，无预编程）；
2. 设备就绪检查（`list_devices` / `read_device`）；
3. 多轮「前进 + 转向 + 取图」逼近目标（共 30 次 `call_device`）；
4. 图像进模型上下文并做出视觉判断；
5. 输出带依据与限制声明的结论。

**诚实的保留（不可省略）**：

| # | 保留 | 说明 |
|---|---|---|
| 1 | 第 647 行出现一次设备 `offline` | 真实中断，未删除；随后自行恢复 |
| 2 | 未能读出**具体刻度数字** | 摄像头仅 640×480，且云台无扭矩（`aim_camera` 必失败），无法放大 |
| 3 | 定位全程 `not trusted` | 无编码器；但任务本就要求「不依赖定位」，与本约束一致 |
| 4 | 输出为自然语言而非严格 JSON | `测试样例_边界.md` 所述的**强制 JSON 输出尚未实现**，此处不得声称已实现 |

> **可复用的部分**：步骤 2–5 已有实测记录，可直接作为本样例的证据基础
> （见 `AGH执行记录与设备调用.md` 第二节）。步骤 1、6–8 需一次完整执行来补。
