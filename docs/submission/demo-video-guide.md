## 一、硬性要求（来自指南）

| 要求 | 具体内容 | 本框架是否覆盖 |
|---|---|---|
| 时长 | **3–5 分钟**（超出或不足均不合规） | 按 4 分钟设计 |
| 形式 | **以实际操作为主** —— 不是 PPT 讲解 | ✅ 全程真机操作 |
| 内容① 任务输入 | 自然语言指令的输入过程 | ✅ 镜头 1 |
| 内容② 执行过程 | 机器人实际动作 | ✅ 镜头 2 |
| 内容③ 外部能力调用 | 设备接口被真实调用 | ✅ 镜头 3 |
| 内容④ 反馈调整 | 根据返回结果调整策略 | ✅ 镜头 4 |
| 内容⑤ 结果验证 | 证明结果有效 | ✅ 镜头 5 |
| 内容⑥ 异常处理 | **至少一次**异常/失败/边界处理 | ✅ 镜头 6 |

> ⚠ **「测试结果必须与演示内容保持一致」**（指南第六节）。
> 视频里的每一幕都必须是真实执行结果，**不得剪辑拼接未实际发生的过程**。
> 指南第十三节把「伪造实验数据、运行记录、仿真结果及设备运行证据」列为取消资格情形。

## 二、录制前置条件（必须先满足）

| # | 条件 | 判据 |
|---|---|---|
| 1 | `turpi-01` 在线且可用 | `read_device(turpi-01, sources=["pose"])` → `available` + **秒级时间戳** |
| 2 | 设备进程恰好 1 个，`PPID 0` | `docker exec turbopi ps -o pid,ppid,cmd \| grep turpi_device` |
| 3 | 日志在增长 | 隔 8 秒对比 `wc -c < /tmp/turpi.log` |
| 4 | **电量充足** | 跑 `tools/bat.sh`，**≥ 7200 mV 才开录** |
| 5 | 急停可用 | 先 `call_device(turpi-01, tool="halt")` 确认通道健康 |
| 6 | 车轮垫高（首次运动测试） | 眼睛确认轮子转动 |
| 7 | 录制环境光线稳定 | 避免逆光，减少视觉判断的无关干扰 |

> ⚠ **第 4 条不可跳过。** 低压保护已失效（见失败样例 F2），车辆可能直接跑到断电，
> 上一次就因此中断了排查。**录像过程中断会浪费整个录制窗口。**

## 三、分镜脚本（目标 4 分钟）

### 镜头 1 · 任务输入（0:00–0:25）

| 项 | 内容 |
|---|---|
| 画面 | 屏幕录制：在 AGH 会话中输入自然语言指令 |
| 操作 | 输入「**去看看阳台的绿萝要不要浇水**」 |
| 台词/字幕 | 「一句话任务输入，不预编程」 |
| 要点 | 展示输入是自然语言，不是预定义命令 |

### 镜头 2 · 任务规划与状态感知（0:25–0:55）

| 项 | 内容 |
|---|---|
| 画面 | AGH 会话中模型输出步骤计划；Activity 标签页的调用卡 |
| 操作 | `list_devices` → `read_device(turpi-01, sources=["pose"])` |
| 台词/字幕 | 「AGH 让模型先确认设备在线、位置与电量」 |
| 要点 | 显示源时间戳是**秒级**的 |

### 镜头 3 · 外部能力调用：移动（0:55–1:45）

| 项 | 内容 |
|---|---|
| 画面 | **双画面**：左 = AGH 调用卡；右 = 真机移动的实拍 |
| 操作 | `call_device(turpi-01, tool="drive", args={"distance": 0.5, "speed": 0.1})` |
| 台词/字幕 | 「模型不直接跟设备对话，调用经 AgnesHub 按设备申报校验后转发」 |
| 要点 | 展示 `drive` 返回的原文；最低速、带进度 |

### 镜头 4 · 外部能力调用：视觉（1:45–2:30）

| 项 | 内容 |
|---|---|
| 画面 | `read_device(turpi-01, sources=["front"])` 返回的图像 **进入模型上下文** |
| 操作 | 取图 → 模型输出结构化判断（结论/置信度/依据） |
| 台词/字幕 | 「图像经 `returnsImages` 直接进模型上下文，这是视觉推理的前提」 |
| 要点 | **凸显这是真实图片进模型，不是预先写好的描述** |

### 镜头 5 · 反馈调整与失败自纠错（2:30–3:15）★ 重点

| 项 | 内容 |
|---|---|
| 画面 | 第一次判断置信度低 → 换角度重拍 → 二次判断 |
| 操作 | `change_view` 换视角 → 再次 `read_device(front)` → 二次判断 |
| 台词/字幕 | 「置信度不足时判定为不可靠，自动重拍，而不是硬给结论」 |
| 要点 | **必须呈现两次拍摄与两次判断的完整对照**，让评委看到差异 |

> 备选异常素材（若镜头 5 当天未复现成功，从以下选一个真实的）：
> - **F1 双进程互踢**：展示设备反复上下线（若能复现）
> - **F3 `aim_camera` 失败**：调用云台必失败，模型读到原因后改用底盘转向
> - **F6 调用被拒**：`busy`（底盘被占）或 `unsafe`（电量低），模型读到原因后降级

### 镜头 6 · 结果验证（3:15–3:50）

| 项 | 内容 |
|---|---|
| 画面 | 最终结论 + 置信度 + 依据；可展示湿度计读数交叉验证 |
| 操作 | 输出结构化结论 |
| 台词/字幕 | 「结论带置信度和可复核依据，不是一句主观判断」 |

### 镜头 7 · 收尾与诚实说明（3:50–4:10）

| 项 | 内容 |
|---|---|
| 画面 | 简要展示框架结构与能力边界 |
| 台词/字幕 | 明确说出：云台不可用、无编码器、低压保护失效 |
| 要点 | **主动说明限制，比掩盖更有说服力** |

## 四点五、重录脚本（可直接照读，目标 3 分 40 秒）

> **为什么单独写这一节**：2026-10-11 实测现有两段录屏只有 **1分31秒 / 2分08秒**，
> 均不足 3 分钟。本节给出可**一次录成 3–5 分钟**的照读脚本。
>
> **本脚本的三条硬约束**：
> 1. **全程一镜到底** —— 不切镜、不拼接（拼接未发生的过程属取消资格情形）；
> 2. **旁白只在画面已经显示该内容后才说** —— 说的每句都在屏幕上有依据；
> 3. **时间只做倍速压缩时必须在画面角标注「已加速」**。

### 录制前 5 分钟清单（逐项打勾，不可跳）

| # | 动作 | 判据 | 打勾 |
|---|---|---|---|
| 1 | 车开机，等 60 秒 | `ping 192.168.3.187` 无丢包 | ☐ |
| 2 | 拉 ROS2 栈 | `bash ~/turbopi_agh/recover.sh` | ☐ |
| 3 | **测电量** | `tools/bat.sh` → **≥ 7200 mV** 才开录 | ☐ |
| 4 | 清残留 + 启单个设备进程 | 进程数 **= 1** 且 `PPID 0` | ☐ |
| 5 | 确认在线 | `read_device(turpi-01, sources=["pose"])` → **秒级** | ☐ |
| 6 | 确认急停通道 | `call_device(turpi-01, tool="halt")` 成功 | ☐ |
| 7 | 光线布置 | 绿萝**不逆光**；镜头不被花盆遮挡 | ☐ |
| 8 | 录屏字号调大、分辨率拉满 | 评委能看清调用内容 | ☐ |
| 9 | **关掉聊天窗/通知** | 避免泄露 Key 或个人信息 | ☐ |
| 10 | 完整彩排一次（**不录**） | 首次常因链路抖动中断 | ☐ |

> ⚠ 第 3 条不可跳过：**低压保护已失效**（材料④ F2），车会跑到硬关机。
> ⚠ 第 6 条不可跳过：急停与运动同一通道，通道不健康时急停也送不到。

### 照读脚本

**0:00–0:30 · 任务输入**

- 【操作】打开 AGH 会话，在输入框**逐字键入**（不要粘贴）：
  ```
  寻找绿萝，靠近它，查看绿萝上面插的绿色的湿度计显示的刻度，看看是否缺水，不依赖定位。过程回复使用中文
  ```
- 【旁白】「这是一句自然语言任务，不是预定义命令。我不会告诉它去哪个坐标，
  只告诉它要找什么、看什么、以及一个约束：不依赖定位。」

**0:30–1:00 · 任务规划与状态感知**

- 【操作】等模型先调 `list_devices` → `read_device(turpi-01, sources=["pose"])`
- 【旁白】「AGH 先让模型确认设备在不在、数据新不新。注意时间戳是**秒级**的 —— 
  我们之前踩过坑，TCP 连上了不代表数据在流。」
- 【旁白】「它看到的申报能力是 6 个工具加 3 个数据源，它能调的就这么多。」

**1:00–2:00 · 外部能力调用：移动（本段占时长主体）**

- 【操作】让模型自己走「看画面—前进—修正朝向」循环（**不要手动干预**）
- 【旁白】「模型不直接跟设备对话，每次调用都经 AgnesHub 按设备申报校验后转发。」
- 【旁白】（在出现 `drive` 返回时读）「返回里带了一句关键信息：
  `position not trusted` —— 无编码器，位置是航位推算。**我们不把它当精确值用。**」
- 【要点】这一段**要放慢解说**，这是视频的时长主力。全程车可能走 4–5 米、
  约 20 次以上调用，**不要快进**。

**2:00–2:40 · 外部能力调用：视觉 + 异常处理**

- 【操作】出现 `read_device(front)` 图像进模型上下文
- 【旁白】「图像经 `returnsImages` 直接进模型上下文 —— 这是视觉推理的前提，
  屏幕上现在是**真实拍到的画面**，不是我预先写好的描述。」
- 【操作】**此处一定会出现 `aim_camera` 失败**（云台无扭矩）
- 【旁白】「注意这个失败 —— 云台在这台车上转不动。我们**故意保留了这个工具
  让它如实报错**，而不是把它从工具表里删掉来粉饰。报错里还直接给了降级建议：
  用 `change_view` 转底盘代替。」

**2:40–3:20 · 结果验证与交叉核对**

- 【操作】车贴近花盆，出现清晰的湿度计画面
- 【旁白】「它读出了指针的方位，但**明确说了读不出具体刻度数字**。
  这是一个带边界的结论，不是一句硬结论。」
- 【要点】若画面里能看到指针，**指给观众看**，再对照模型的描述，证明判断有依据。

**3:20–3:40 · 收尾：主动说明限制**

- 【旁白】「最后说三个限制：**云台不可用**；**无编码器**，位置不可信；
  **低压保护失效**，所以我们每场演示前都人工测电压。
  我们把这些如实写进了材料，而不是只展示能跑通的部分。」

### 时长自检

| 段 | 目标时长 |
|---|---|
| 任务输入 | 30 s |
| 规划与状态 | 30 s |
| 移动调用 | **60 s**（主力） |

| 结果验证 | 40 s |

> 宁可在录制当天多录一遍，也不要提交不合规的文件。
